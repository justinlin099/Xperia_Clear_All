0.28 CONNECTION RECOVERY
Bounded retries at cumulative 2/6/14/30/60 seconds after unlocked enabled initialization.
Overlay start and real binder-ready/user-present events can resume recovery without Activity onResume.
Repeated lifecycle events do not extend an active window. Successful connection cancels retry tasks.
Worker binding timeout retries a clean bind; user disable immediately removes retry tasks.
Transient STOPPED/WORKER_ERROR states show a silent waiting notification during the window;
CONNECTING shows connection progress. The same notification ID changes to repair on failure.

errors remain actionable. Existing notification permissions/channel choices are preserved.

Handler delays use uptime; deep sleep may extend wall-clock duration. No wake locks, alarms or permanent polling.

Previous retry only inspected the SDK-local binder; it could not acquire a missing server handle.

new permission or external code loading. SDK receives the returned Binder and enforces authorization.
Callback transaction1 accepts only installed manager UID. Null/stale/disabled replies do not connect.

SENT journal entry means submitted broadcast; RECEIVED means actual manager reply.
